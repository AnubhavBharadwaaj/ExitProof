# Evidence: eight leaks that shaped every feature

ExitProof was designed backwards from evidence. Before writing code we traced one exit end to end with three practitioners (a labour law advocate, a multi state HR compliance consultant, a security operations practitioner), our own exit experience, and public sources. Each finding broke an assumption a normal HR workflow makes, and each feature exists because of one of them.

| # | What we found | Source | Feature |
| --- | --- | --- | --- |
| L1 | A resignation does not reach the security team as an event. The DLP look back window for a leaver is a per company choice: the whole notice period, the last month, or the last week. | Practitioner conversation, Nov 2026 | F6 SOC Bridge, F7 Notice Window Policy |
| L2 | On the last day four separate teams each remove only their own slice: identity and privileged access, email and SharePoint, desktop and the user account, physical cards. No one holds the full list. | Practitioner conversation | F2 Leaver Access Graph |
| L3 | The exit ticket lives in an ITSM tool owned by IT, not HR, and is kept for audit; the real confirmations happen by email. Security tickets are different: they are generated automatically from SIEM alerts with every detail inside. | Practitioner conversation | F5 Inbox Closer, F6 SOC Bridge |
| L4 | Access a team set up for itself, such as cloud keys or a shared login for a paid tool, is left to that team; a central disable does not touch it. In 2018 a former Cisco engineer used cloud access five months after leaving to delete 456 VMs, taking down 16,000 Webex Teams accounts for up to two weeks. | Practitioner conversation; [US DOJ](https://www.justice.gov/usao-ndca/pr/san-jose-man-sentenced-two-years-imprisonment-damaging-cisco-s-network); [The Register](https://www.theregister.com/AMP/2020/08/26/former_cisco_engineer_aws_webex_teams) | F2, F4 Proof of Revocation |
| L5 | Our realisation from L4: for a shared login protected by an authenticator app, changing the password does not remove a leaver, because the app on their phone keeps producing valid codes until the MFA seed is enrolled again. | Our analysis | F3 Shared Secret Rotation |
| L6 | Two legal clocks run at once: wages, including leave encashment, within 2 working days of the last working day; gratuity within 30 days. Practice used to be 30 to 45 days. | Labour law advocate; [LiveLaw](https://www.livelaw.in/articles/two-working-days-code-wages-employee-final-settlement-552780); [PocketHRMS](https://www.pockethrms.com/blog/full-and-final-settlement/); [Petpooja](https://blog.petpooja.com/people-payroll/full-and-final-settlement-india/) | F1 Two Clock Settlement |
| L7 | The Labour Code sets the payment timeline for the first time, but leave entitlement is still defined by each State Shops and Establishments Act. State labour offices inspect, so multi state firms align with state rules. | Multi state HR compliance consultant | F1 state rule packs |
| L8 | One of us kept using a former employer's meal benefit card for a year after leaving. Third party cards sit outside every IT checklist. | Our own experience | F2 (third party items) |

Data protection basis for F7: [DPDP Act s.7(i)](https://www.mondaq.com/india/data-protection/1755320/is-consent-required-to-process-employees-personal-data-under-the-dpdp-act) allows processing for employment and to safeguard the employer, but [not blanket surveillance](https://ksandk.com/md/data-protection-and-data-privacy/can-employers-monitor-employees-dpdp-act/); [DPDP Rules 2025, Rule 6](https://dpdp.myndsolution.com/wiki/rules/rule-6-reasonable-security-safeguards/) requires logs to be kept for one year.
